## 1. 目的・スコープ

### 1.1 目的
「これ欲しい」「今度あそこで買う」と思ったその場で、アプリを開いてすぐ書き留められるようにする。
あとで「100均 › ダイソー」「日用品 › ハック」のようなカテゴリで見返し、調べた内容やリンクも一緒に残せるようにする。
普段の買い物（「スーパーで牛乳」「100均で収納ケース」）も、カテゴリを付けて書いておけば、カテゴリで絞り込むとそのまま買い物リストになる。

### 1.2 主要機能（スコープ内）
| # | 機能 | 概要 |
|---|------|------|
| F1 | すぐ登録 | 開いた画面の入力欄に名前を書くだけで登録できる。カテゴリは任意 |
| F2 | 一覧 | 欲しいものを一覧。新しい順・カテゴリごとに並べ、大カテゴリ・中カテゴリ・キーワードで絞り込む。中カテゴリは名前でまとめる（食品のコストコと日用品のコストコを一緒に出す）。キーワードはカテゴリの名前でも見つかる。左上の丸で買ったものも出す |
| F3 | 詳細・編集 | 1件ごとのページで、名前・値段・カテゴリ・詳細メモ・リンクを見る／直す／消す |
| F4 | カテゴリ（2段） | 大カテゴリ（例: 100均・日用品・家電）と、その中の中カテゴリ（例: 100均 › ダイソー・セリア）。Kakeibo のカテゴリと同じ作り |
| F6 | 買ったチェック | チェックボックスで「買った」を付ける。外せば戻る |
| F7 | リンク | 調べたページの URL を複数つけられる |
| F8 | おる | Kakeibo のキャラクター「おる」が、アプリを開いたときなどにときどき出てきてひとことしゃべる |

（F5「購入先ごとの値段の比較」は v0.6 でやめた。番号は v0.5 までと合わせるため欠番）

### 1.3 スコープ外（初期リリースでは対応しない）
- 予算の管理、家計簿への連携（買ったら家計簿に記録、など）
- 購入先ごとの値段の比較（v0.6 でやめた。値段はメモに1つ入れられる）
- 画像の添付（R2 を使わない構成にする。必要になったら Kakeibo の受け取り処理を流用して追加）
- リンク先のタイトル・画像の自動取得（OGP）。§9 フェーズ2の候補
- 共有シート（他のアプリから「共有」でメモに送る）。iPhone の PWA は Web Share Target に対応していないため
- 通知（Web Push）

## 2. 想定ユーザー・利用環境

- 利用者: Kakeibo と同じ。管理者（最初にセットアップした1名）と、招待したメンバー（2人）
- **全員で1つのメモ帳を共有する**。誰が追加したメモでも、見る・直す・消す・買ったを付けることができる。メモには追加した人を残す
- 端末: 主に iPhone（ホーム画面に追加した PWA）。PC のブラウザでも使う
- 提供形態: Web アプリ（PWA）。Kakeibo とは別のアプリ・別の URL・別のホーム画面アイコン

### 2.1 PWA・レスポンシブ
Kakeibo の §2.1・§2.2 と同じ決まりにする。

| 画面幅 | レイアウト |
|--------|------------|
| 〜767px（スマホ） | 1カラム。一覧 → 押すと詳細ページへ移る。入力欄は画面下（親指が届く位置）に固定 |
| 768〜1023px | 1カラム。一覧の幅を広げる |
| 1024px〜（PC） | 2カラム。左に一覧、右に選んだメモの詳細を常に表示。入力欄は一覧の上 |

- `display: standalone`、`viewport-fit=cover` と `env(safe-area-inset-*)`、入力欄は 16px 以上（自動ズーム防止）
- 画面の明るさ（自動・ライト・ダーク）は端末ごとに切り替え（Kakeibo の `public/theme.js` と同じ仕組み）

## 3. 用語

| 用語 | 定義 |
|------|------|
| メモ | 欲しいもの1件の記録 |
| 名前 | メモの見出し（例: ブックスタンド）。必須 |
| 値段 | メモの値段（円・整数・任意。0〜9,999,999）。1件のメモに1つ |
| 大カテゴリ | メモの分け方の大きい方（例: 100均、日用品、家電）。1件のメモに0〜1個 |
| 中カテゴリ | 大カテゴリの中の分け方（例: 100均 › ダイソー、日用品 › ハック）。1件のメモに0〜1個。大カテゴリを選んでいるときだけ選べる |
| 詳細メモ | 名前だけでは足りない内容（サイズ、型番、気になる点など）を書く自由記述欄 |
| リンク | 調べたページの URL と、任意の表示名 |
| 買った | メモの状態。チェックすると欲しいものの一覧から外れ、いちばん下の「買ったもの」（ふだんは畳んである）に入る |

## 4. 機能要件

### F1. すぐ登録（いちばん大事な機能）

- アプリを開いた最初の画面（一覧）に、常に入力欄を出す。名前を書いて「追加」（Enter）で登録できる
- 入力欄の下の「カテゴリ」から、大カテゴリと中カテゴリを選べる（任意）。選んだものは「100均 › ダイソー」のように色付きのラベルで出す
  - 登録したらカテゴリも選び直しにする（前に選んだものは残さない）。一覧を大カテゴリで絞り込んでいるときは、その大カテゴリを選んだ状態にする
  - 一覧を大カテゴリで絞り込んでいるときは、その大カテゴリを初めから選んだ状態にする
- 登録したら入力欄を空にして入力を続けられる状態にし、一覧に追加する（画面の読み直しなし）
- 入力欄の右の「詳しく」から、全項目（名前・値段・大カテゴリ・中カテゴリ・詳細メモ・リンク）をまとめて書くシートを開ける
  - 大カテゴリはアイコンの一覧から選び、選んだ大カテゴリの中カテゴリをボタンから選ぶ。どちらもその場で追加できる（Kakeibo の入力画面と同じ作り）
- **音声入力**（v0.14）：入力欄と「追加」の間のマイクを押すと録音が始まり、もう一度押す（または止めるボタン）で止まる
  - 録音中は「聞いています…」の画面を出し、声の大きさに合わせて波線と止めるボタンの周りの光が動く（拾えているかが見て分かる）。60秒で自動で止める
  - 録音は画面で 16kHz・モノラルの WAV にして `POST /api/voice` に送る。サーバーは Gemini（Kakeibo と同じ `gemini-3.5-flash-lite`）に音声と今のカテゴリの一覧を渡し、聞き取りと整理を1回で行う。音声は保存しない
  - Gemini には、名前は短く・値段は言われたときだけ・大カテゴリは一覧から1つ・中カテゴリは話に出たお店などが合うときだけ・詳細メモは必要な情報だけ短く、を指示する。返ってきたカテゴリは名前から ID に直し、今あるものだけを使う
  - 「以下を登録します」の確認画面に、聞き取った内容と下書き（複数なら全部）を並べる。名前・カテゴリ・値段・詳細メモをその場で直し、要らないものは外して、まとめて登録する
  - 1人1日50回まで（`voice_usage`）。`GEMINI_API_KEY` が未設定の間はお試し版（固定のサンプル）を返し、確認画面にそう出す
- 開いたときのキーボード: PC は入力欄に自動でカーソルを置く。iPhone は Safari の制約で、利用者が押すまでキーボードを出せない（§11 リスク）。そのため入力欄は大きく、画面下の押しやすい位置に置く

### F2. 一覧

- ふだんは欲しいもの（まだ買っていないもの）だけを出す
- **左上の丸**を押すと、買ったものも一覧のいちばん下に「買ったもの」の見出しでまとめて出す（もう一度押すと隠す。端末ごとに覚える）。丸に件数は出さない。買ったものが0件なら「まだ買ったものはありません」と出す
- 並べ方は2つ（端末ごとに覚える）
  - **新しい順**（初期）: 追加した新しい順に1列。各行にカテゴリのラベル（大カテゴリの色の枠で囲んだ丸いラベル）を出す
  - **カテゴリごと**: 大カテゴリの見出しの下に、中カテゴリの小見出しでまとめる。中カテゴリのないメモは「そのほか」、大カテゴリのないメモは最後の「カテゴリなし」
- 絞り込み: 大カテゴリ・キーワード（名前・詳細メモ・リンクの表示名から探す）
- 値段を入れたメモは、行の右に値段を出す
- 行を押すと詳細ページ（F3）へ。PC は右側に表示

### F3. 詳細・編集

- URL を持つ個別のページにする（`/m/<メモID>`）。ブラウザの戻る・PC での直接アクセスに対応
- 上から: 「買った」のチェックボックスと名前、カテゴリのラベルと値段、詳細メモ（複数行・改行そのまま表示）、リンク
- 「直す」で F1 の「詳しく」と同じシートを開く。保存せずに離れようとしたら確認する
- 削除は確認してから。削除したあと数秒「元に戻す」を出す。消したメモはサーバーに7日間残し（`deleted_at`）、毎日の後片付けで消す
- 追加した人・作成日時・更新日時を小さく表示（「〇〇が追加」）。買ったものは「〇〇が買った・日付」も出す

### F4. カテゴリ（大カテゴリ › 中カテゴリ）

Kakeibo の「カテゴリ › 中カテゴリ」と同じ作り。

- 大カテゴリ: 名前・アイコン・色。追加・名前変更・並べ替え（つまみのドラッグ、キーボードは↑↓）・削除。色は決まった色か、グラデーションから作る
- 中カテゴリ: 大カテゴリの編集画面で追加・名前変更・削除。入力画面からもその場で追加できる。同じ名前を別の大カテゴリに作れる
- 設定の「カテゴリの管理」で一覧（使っているメモの件数・中カテゴリの名前つき）
- 大カテゴリを消すとき、使っているメモがあれば「別の大カテゴリへ移す（中カテゴリは外れる）」か「移さずに外す」を選ぶ。中カテゴリも一緒に消える
- 中カテゴリを消すと、使っているメモは中カテゴリなしになる
- 初期の値（初回セットアップで作る。あとで自由に変更）: 100均（ダイソー・セリア・キャンドゥ）、日用品（ドラッグストア）、食品（スーパー）、家電（ヨドバシ・ビックカメラ・Amazon）、家具（ニトリ・IKEA・無印良品）、服、その他

### F6. 買ったチェック

- 一覧の各行と詳細ページの名前の左にチェックボックスを出す。押すとすぐ「買った」になる（保存ボタンは不要）
- 「買った」にしたメモは一覧から外れる。数秒「元に戻す」を出す
- 買った人と買った日時（チェックを付けた日時）を残す。買ったものの詳細には名前の下に「10/12に買った」と出す。買う前のものには出さない
- おるが「買えたね！」とお祝いすることがある（F8）

### F7. リンク

- 1件のメモに最大10件。URL（必須）と表示名（任意。空なら URL のドメインを表示）
- 貼り付けた文字列から URL を取り出す（共有で付く前後の文章を除く）
- `http://` `https://` 以外は受け付けない（`javascript:` などを防ぐ）。2,048文字まで
- 押すと別タブで開く（`rel="noopener noreferrer"`）

### F8. おる（定期的に出てくる）

Kakeibo の「おる」（`components/Oru.tsx`・`OruCameo.tsx`・`lib/oru.ts`・`public/mascot/oru-sheet.webp`）をそのまま使い、しゃべる内容だけメモ向けにする。

- 出てくるとき: アプリを開いたとき・ほかのアプリから戻ってきたときに2回に1回くらい。前に出てから5分はあける（Kakeibo と同じ `ORU_CHANCE = 0.5`・`ORU_GAP_MS = 5分`）
- 画面の右下（スマホは入力欄の少し上）から歩いてきて、ひとことしゃべって帰る。押すとすぐ帰る。吹き出しはしゃべり終わって3秒で消える
- 入力中・シートを開いている間は出さない（すぐ登録の邪魔をしない）
- メモを追加したとき・買ったを付けたときに、ときどき（5回に1回くらい・5分あける決まりは同じ）ジャンプして「メモしたよ！」「買えたね！」などと言う
- しゃべる内容
  - 普通のひとこと（例: 「欲しいもの、思いついた？」「メモしておけば忘れないよ」「カテゴリで絞り込むと、お店ごとのリストになるよ」）
  - 時間帯のひとこと（Kakeibo の `timeLines` を流用し、文面をメモ向けに変える）
  - メモの数字のひとこと（例: 「ダイソーのメモが3件あるよ。今度まとめて買おう」「1か月前のメモ、まだ欲しい？」）
- 設定の「表示」で端末ごとにオフにできる。「視差効果を減らす」の端末では動かさない

## 6. データ要件

### 6.1 テーブル（D1）

正式な定義は `migrations/`（0001 認証・メモ、0002 大カテゴリ・中カテゴリ、0003 メモの値段）。要点:

| 表 | 中身 |
|------|------|
| `categories` | 大カテゴリ（名前・アイコン・色・並び順）。名前は重複不可 |
| `subcategories` | 中カテゴリ（大カテゴリ・名前・並び順）。同じ大カテゴリの中で名前は重複不可。大カテゴリを消すと一緒に消える |
| `memos` | 名前・詳細メモ・値段（`price`）・`category_id`・`subcategory_id`・買った日時と人・追加した人・作成／更新日時・消した日時（7日間残す）・送り直し用の `client_id` |
| `memo_links` | メモのリンク（URL・表示名・並び順） |
| 認証まわり | `users` / `credentials` / `sessions` / `auth_challenges` / `recovery_codes` / `invites` / `auth_failures` / `auth_logs`（Kakeibo から） |

- 0003 で、`memo_offers` に残っていた値段（購入先が複数あればいちばん安いもの）をメモの値段に戻した
- v0.5 までの `stores`（購入先）・`genres`（ジャンル）・`memo_offers`（購入先ごとの値段）と `memos.genre_id` は、表を残したまま使わない（前に入れた値を消さないため）。0002 のマイグレーションで、購入先・ジャンルの名前が同じ大カテゴリ・中カテゴリへメモを移した（例: 購入先「100均」→ 大カテゴリ「100均」）
- 中カテゴリは、その大カテゴリの中のものだけを受け付ける（サーバーで確認）
- 件数の見込み: 2人で年に数百件。一覧は1回の問い合わせでまとめて読み、絞り込み・並べ方は画面側で行う

### 6.2 API（Hono、`/api/*`）

| メソッド・パス | 内容 |
|------|------|
| `GET /api/data` | 画面を開いたときに読む全部（大カテゴリ（中カテゴリつき）・消していない全メモ（リンクつき）） |
| `POST /api/memos` | 登録（名前だけでも可） |
| `GET /api/memos/:id` | 詳細 |
| `PATCH /api/memos/:id` | 編集（大カテゴリと中カテゴリは組で送る。リンクは全件送って置き換え。`baseUpdatedAt` が違えば 409） |
| `PUT`・`DELETE /api/memos/:id/done` | 買ったを付ける・外す |
| `DELETE /api/memos/:id`・`POST /api/memos/:id/restore` | 削除（7日間は印を付けるだけ）・元に戻す |
| `GET`・`POST /api/categories`、`PATCH`・`DELETE /api/categories/:id`、`POST /api/categories/reorder` | 大カテゴリ（削除は移し先を指定できる） |
| `POST /api/categories/:id/subcategories`、`PATCH`・`DELETE /api/categories/subcategories/:id` | 中カテゴリ |
| `GET /api/export.csv` | 全メモを CSV（1件で1行）で書き出し |
| `POST /api/voice` | 録音（WAV・3MB まで）からメモの下書きを作る（登録はしない。1人1日50回まで） |
| `/api/auth/*`・`/api/admin/*` | Kakeibo と同じ（ログイン・パスキー・招待・メンバー） |

- 入力チェックは zod のスキーマを `src/shared/schemas.ts` に置き、画面と API で同じものを使う
- 共有のメモ帳なので、2人が同じメモを同時に直したときは、先に保存した方が残る。後から保存した方は 409 で断り、最新を読み直す
- ほかの人の変更は、次のときに「変わった番号」（`sync_state.revision`）だけをサーバーに聞き、前に読んだときから変わっていれば一覧を読み直して取り込む（v0.8）
  - ホームに戻ってきたとき・ホームを開いているあいだ15秒おき・アプリに戻ってきたとき・つながり直したとき
  - 番号はメモ・リンク・大カテゴリ・中カテゴリが変わるたびに DB のトリガーで1上がる。確認で読むのは1行だけ（`GET /api/revision`）
  - 画面が見えていないとき・自分の変更を送っている途中は聞かない（送っている途中に読み直して、画面が一瞬古い内容に戻らないようにする）。送信中で仮に出しているメモは読み直しても残す
  - 相手が追加した瞬間に出る本当のリアルタイム（Durable Objects など）は、2人用には仕組みが重いので使わない

## 8. 技術構成

Kakeibo と同じ構成にする。違いは「R2・AI・Web Push・Cron の大半を使わない」ことだけ。

| 層 | 技術 |
|----|------|
| 画面 | React 19 + TypeScript + Vite（PWA）、Tailwind CSS v4、lucide-react、LINE Seed JP（同梱フォント）、clsx |
| API | Cloudflare Workers + Hono（画面ファイルの配信も同じ Worker。`assets.run_worker_first: ["/api/*"]`） |
| DB | Cloudflare D1（SQLite） |
| 認証 | Kakeibo と同じパスキー（@simplewebauthn）＋リカバリーコード、招待制。実装を移植する（§8.4） |
| 入力チェック | zod（画面と API で共有） |
| Cron | 毎日1回、期限切れのセッション・認証チャレンジ・招待を消す |
| テスト | vitest（単体）＋ @cloudflare/vitest-pool-workers（D1 込みの結合テスト）＋ Playwright（E2E・画面幅ごとの見た目） |
| CI / 公開 | GitHub Actions。Kakeibo の `ci.yml`・`deploy.yml` を流用（main の CI が通ったら `wrangler deploy`） |

### 8.1 デザインの統一のしかた

Kakeibo から次をコピーして持ってくる。見た目の決まりは Kakeibo の `styles.css` の先頭コメントのとおり（白地・細い線で区切る・影とグラデーションは浮くものだけ）。**アクセントの色は Kakeibo と同じオレンジ**（`--c-brand: #cc4a0b`、ダークは `#fb923c`）をそのまま使う。

| 持ってくるもの | Kakeibo の場所 |
|------|------|
| 色・文字サイズ・アニメーションのトークン（ライト/ダーク） | `src/client/styles.css` |
| 画面の明るさの切り替え | `public/theme.js`・`src/client/lib/theme.ts` |
| シート（下から出る・払って閉じる）・トースト | `components/Sheet.tsx`・`components/Toast.tsx` |
| 金額の表示・入力 | `shared/format.ts`・`components/AmountInput.tsx` |
| カテゴリのアイコン・選択・編集・中カテゴリ・管理 | `shared/icons.ts`・`components/CategoryIcon.tsx`・`CategoryPicker.tsx`・`SubcategoryPicker.tsx`・`CategoryEditor.tsx`・`SubcategoryManager.tsx`・`views/CategoryManager.tsx`（このアプリでは `TagIcon.tsx`・`CategoryPicker.tsx`・`CategoryEditor.tsx`・`views/CategoryManager.tsx` にまとめた） |
| おる | `components/Oru.tsx`・`OruCameo.tsx`・`lib/oru.ts`・`public/mascot/oru-sheet.webp` |
| ログイン・パスキー・招待 | `views/AuthScreens.tsx`・`worker/routes/auth.ts`・`worker/lib/session.ts`・`worker/lib/crypto.ts`・`worker/lib/http.ts` |
| 端末内の保存・更新の検知・振動 | `lib/storage.ts`・`lib/update.ts`・`lib/haptics.ts`・`public/sw.js`・`public/_headers` |

- 共通パッケージ（モノレポや npm パッケージ）にはしない。アプリが2つ・作るのが1人なので、まとめる手間の方が大きい。コピーしたファイルの先頭に「Kakeibo の〇〇から」と書き、Kakeibo 側で直したら合わせる
- アプリが3つ目になる、またはコピー元との差が目立ってきたら、共通部分を別パッケージにまとめることを検討する
- ホーム画面で見分けられるよう、アイコンは別の絵にする（色は同じオレンジ）。絵は `design/icon-original.png`（いただいた画像）から `scripts/prepare-icon-source.py` で角丸の外の灰色と縁の光沢を外し、`design/icon-source.png`（1024px 四方・角丸なし）を作って、Kakeibo と同じ `npm run icons` で各サイズを作る

### 8.2 ディレクトリ構成

```
src/client     画面（React）。views/ 画面、components/ 共通部品、lib/ 保存・テーマ・おる・一覧の組み立て
src/worker     API（Hono）。routes/（auth / memos / stores / genres / admin）、lib/（セッション・暗号・HTTP）
src/shared     画面と API で共有する型・入力チェック・日付・金額
migrations     D1 のテーブル定義（0001 認証・メモ、0002 大カテゴリ・中カテゴリ）
public         manifest / Service Worker / アイコン / おるの画像 / _headers
test/worker    Workers 結合テスト
e2e            ブラウザでの動作確認
```

### 8.3 Kakeibo に組み込む案を採らない理由
Kakeibo の中に「メモ」タブを足せば認証やデザインを共有できるが、次の理由で別アプリにする。
- 「開いてすぐ書ける」ことが目的なので、メモだけの画面で起動したい（Kakeibo はカレンダーで起動する）
- Kakeibo は機能が多く、変更のたびに確かめる範囲が広い。メモの変更で家計簿を壊す心配をなくしたい

### 8.4 ログイン（パスキー）
- Kakeibo と同じしくみ（パスキーだけ・招待制・リカバリーコード）を移植する。使い方（Face ID で入る）は Kakeibo と同じ
- ただし**パスキーそのものは Kakeibo と別に1回登録する**。パスキーはアプリの URL（ホスト名）に結びつき、Kakeibo は自分のホスト名で登録しているため（`worker/routes/auth.ts` の `rpID`）、別の URL のメモアプリでは同じパスキーを使えない
- 同じパスキーで両方に入るには、両方を同じドメインの下に置き（例: `kakeibo.example.com` と `memo.example.com`）、パスキーの登録先を親ドメイン（`example.com`）にする必要がある。Kakeibo の今のパスキーは作り直しになるため、採らない

## 11. リスク・懸念

| リスク | 内容 | 対応 |
|------|------|------|
| iPhone でキーボードが自動で出ない | iOS の Safari・ホーム画面アプリは、利用者が押す前に入力欄へカーソルを置いてもキーボードを出さない。「開いたらすぐ打てる」はタップ1回が必要 | 入力欄を画面下の大きな的にする。どうしても0タップにしたい場合はフェーズ3の iPhone のショートカット連携で補う |
| 2人の同時編集 | 同じメモを同時に直すと、後から保存した方が残る | `updated_at` で検知して知らせる（§6.2） |
| デザインのずれ | コピーした部品が Kakeibo と少しずつずれていく | コピー元を各ファイルの先頭に書く。差が大きくなったら共通化（§8.1） |
| リンクの安全 | 利用者が貼った URL を画面に出す | `http`/`https` だけ受け付け、`noopener noreferrer` で開く。CSP は Kakeibo の `_headers` を流用 |
| LINE から開くとパスキーを作れない | 招待リンクを LINE から開くと（「ブラウザで開く」を使っても）、iPhone が「QRコードまたはセキュリティキー」しか出さず登録できないことがあった | 招待リンクの作成画面と共有の文面で「コピーして Safari のアドレス欄に貼り付けて開く」と案内する。登録画面でも、アプリの中で開いたときや失敗したときに同じ案内を出す |
| ログインが2つになる | Kakeibo とメモでパスキーを別々に登録する | 初回の登録だけの手間（§8.4） |
| おるの出すぎ | メモは短時間に何度も開くため、出てくる回数が Kakeibo より多くなりうる | 5分あける決まりを守る。多すぎれば確率を下げる |
