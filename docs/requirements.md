# 欲しいものメモ 要件定義書

- 版数: v0.2
- 作成日: 2026-10-12
- 更新日: 2026-10-12（v0.2: カテゴリを「購入先」と「ジャンル」の2軸に変更、購入先ごとの価格比較、買ったチェック、決定事項の反映）
- ステータス: 方針確定。残りの確認事項は §10.2
- 前提: [Kakeibo](https://github.com/Riku4230/kakeibo)（2人の家計簿）と同じデザイン・技術構成・運用のしかたにそろえる

## 1. 目的・スコープ

### 1.1 目的
「これ欲しい」「今度あそこで買う」と思ったその場で、アプリを開いてすぐ書き留められるようにする。
あとで「どこで買うか」「どんなものか」で探して見返し、お店ごとの値段・調べた内容・リンクも一緒に残して比べられるようにする。

### 1.2 主要機能（スコープ内）
| # | 機能 | 概要 |
|---|------|------|
| F1 | すぐ登録 | 開いた画面の入力欄に名前を書くだけで登録できる。ジャンル・購入先は任意 |
| F2 | 一覧 | すべてのメモを一覧。購入先・ジャンル・キーワードで絞り込み、「購入先 › ジャンル」の2段で見られる |
| F3 | 詳細・編集 | 1件ごとのページで、名前・ジャンル・購入先ごとの候補・詳細メモ・リンクを見る／直す／消す |
| F4 | カテゴリ（2軸） | 「購入先」（例: ヨドバシ、Amazon）と「ジャンル」（例: 洗濯機）を別々に管理し、別々に選ぶ |
| F5 | 購入先ごとの候補（価格比較） | 1件のメモに購入先を複数つけ、それぞれに値段・リンク・ひとことを残す（例: 洗濯機 — ヨドバシ 189,800円 / Amazon 179,000円） |
| F6 | 買ったチェック | チェックボックスで「買った」を付け、一覧の「買ったもの」に分ける。外せば戻る |
| F7 | リンク | 購入先に関係しない調べたページ（レビュー記事など）の URL を複数つけられる |
| F8 | おる | Kakeibo のキャラクター「おる」が、アプリを開いたときなどにときどき出てきてひとことしゃべる |

### 1.3 スコープ外（初期リリースでは対応しない）
- 予算の管理、家計簿への連携（買ったら家計簿に記録、など）
- 値段の自動取得・値下がりの通知（値段は自分で書く）
- 画像の添付（R2 を使わない構成にする。必要になったら Kakeibo の受け取り処理を流用して追加）
- リンク先のタイトル・画像の自動取得（OGP）。§9 フェーズ2の候補
- 共有シート（他のアプリから「共有」でメモに送る）。iPhone の PWA は Web Share Target に対応していないため
- 通知（Web Push）

## 2. 想定ユーザー・利用環境

- 利用者: Kakeibo と同じ。管理者（最初にセットアップした1名）と、招待したメンバー（2人）
- **全員で1つのメモ帳を共有する**。誰が追加したメモでも、見る・直す・消す・買ったを付けることができる。メモには追加した人を残す
- 端末: 主に iPhone（ホーム画面に追加した PWA）。PC のブラウザでも使う
- 提供形態: Web アプリ（PWA）。Kakeibo とは別のアプリ・別の URL・別のホーム画面アイコン

### 2.1 PWA・レスポンシブ
Kakeibo の §2.1・§2.2 と同じ決まりにする。

| 画面幅 | レイアウト |
|--------|------------|
| 〜767px（スマホ） | 1カラム。一覧 → 押すと詳細ページへ移る。入力欄は画面下（親指が届く位置）に固定 |
| 768〜1023px | 1カラム。一覧の幅を広げる |
| 1024px〜（PC） | 2カラム。左に一覧、右に選んだメモの詳細を常に表示。入力欄は一覧の上 |

- `display: standalone`、`viewport-fit=cover` と `env(safe-area-inset-*)`、入力欄は 16px 以上（自動ズーム防止）
- 画面の明るさ（自動・ライト・ダーク）は端末ごとに切り替え（Kakeibo の `public/theme.js` と同じ仕組み）

## 3. 用語

| 用語 | 定義 |
|------|------|
| メモ | 欲しいもの1件の記録 |
| 名前 | メモの見出し（例: ドラム式洗濯機）。必須 |
| ジャンル | どういうものか（例: 洗濯機、冷蔵庫、シャンプー）。1件のメモに0〜1個 |
| 購入先 | どこで買うか（例: ヨドバシ、ビックカメラ、Amazon、無印良品）。1件のメモに0個以上 |
| 候補 | メモと購入先の組み合わせ1つ。値段・リンク・ひとこと・値段を確かめた日を持つ |
| 詳細メモ | 名前だけでは足りない内容（候補の型番、サイズ、気になる点など）を書く自由記述欄 |
| リンク | 購入先に関係しない、調べたページの URL と任意の表示名 |
| 買った | メモの状態。チェックすると「欲しい」から「買ったもの」に移る |

## 4. 機能要件

### F1. すぐ登録（いちばん大事な機能）

- アプリを開いた最初の画面（一覧）に、常に入力欄を出す。名前を書いて「追加」（Enter）で登録できる
- 入力欄の下に「ジャンル」「購入先」のボタンを出し、別々に選べる（どちらも任意）
  - ジャンルは1つ、購入先は複数選べる。値段はここでは聞かない（詳細ページで書く）
  - 直前に選んだジャンル・購入先を覚えておき、次の入力でも選んだ状態にする（端末ごと）。✕で外せる
  - 一覧を絞り込んでいるときは、そのジャンル・購入先を初めから選んだ状態にする
- 登録したら入力欄を空にして入力を続けられる状態にし、一覧に追加する（画面の読み直しなし）
- 値段・詳細メモ・リンクは登録後に詳細ページで足す。入力欄の「詳しく書く」から全項目をまとめて書くシートも開ける
- 開いたときのキーボード: PC は入力欄に自動でカーソルを置く。iPhone は Safari の制約で、利用者が押すまでキーボードを出せない（§11 リスク）。そのため入力欄は大きく、画面下の押しやすい位置に置く
- 電波がないときは端末に保存して、つながったら送る（Kakeibo の `lib/offline.ts` を流用）。フェーズ2で対応（§9）

### F2. 一覧

- 上に「欲しい」「買ったもの」の切り替え。初期は「欲しい」
- 並べ方を3つから選べる（端末ごとに覚える）
  - **新しい順**（初期）: 作成日時の新しい順に1列
  - **購入先ごと（2段）**: 購入先の見出しの下に、ジャンルの小見出し、その下にメモ。例: 「ヨドバシ › 洗濯機 › ドラム式洗濯機 189,800円」。購入先が2つあるメモは両方の見出しの下に出て、それぞれの購入先での値段を出す。購入先のないメモは「購入先なし」、ジャンルのないメモは「その他」に入れる
  - **ジャンルごと**: ジャンルの見出しの下にメモ。各メモに購入先ごとの値段を並べる（例: 「ヨドバシ 189,800 / Amazon 179,000」）
- 1行に出すもの
  - 左に「買った」のチェックボックス（F6）
  - 名前、ジャンル、購入先（複数なら「ヨドバシ ほか1件」）
  - 値段: いちばん安い候補の値段（例: 「179,000円〜」）。並べ方が「購入先ごと」のときは、その購入先の値段
  - 詳細メモの1行目（あれば）
- 絞り込み
  - 購入先とジャンルのチップ（横スクロール）。両方選ぶと「両方に当てはまるもの」
  - キーワード（名前・詳細メモ・候補のひとこと・リンクの表示名から探す）
- 行を押すと詳細ページ（F3）へ。PC は右側に表示

### F3. 詳細・編集

- URL を持つ個別のページにする（`/m/<メモID>`）。ブラウザの戻る・PC での直接アクセスに対応
- 上から: 「買った」のチェックボックスと名前、ジャンル、購入先ごとの候補（F5）、詳細メモ（複数行・改行そのまま表示）、リンク（F7）
- 編集はその場で直して「保存」。保存せずに離れようとしたら確認する
- 削除は確認してから。削除したあと数秒「元に戻す」を出す（Kakeibo の Toast）
- 追加した人・作成日時・更新日時を小さく表示（「〇〇が追加」）。買ったものは「〇〇が買った・日付」も出す

### F4. カテゴリ（購入先とジャンルの2軸）

購入先とジャンルは互いに独立した2つの一覧として持つ。決まった組み合わせはない（「洗濯機」はヨドバシでも Amazon でも選べる）。見せるときに「購入先 › ジャンル」の2段にする（F2）。

- 購入先・ジャンルそれぞれ: 名前・アイコン（Kakeibo の `CATEGORY_ICON_KEYS` から選ぶ）・色。追加・名前変更・並べ替え（ドラッグ、キーボードは↑↓）・削除
- 入力・編集画面の選択シートから、その場で新しい購入先・ジャンルを追加できる
- 削除するとき、使っているメモがあれば件数を出して確認する
  - ジャンル: そのメモは「ジャンルなし」になる（ほかのジャンルに移すこともできる）
  - 購入先: そのメモから購入先（値段・リンク・ひとことを含む候補）が外れる。ほかの購入先へ移すこともできる（移し先に同じメモの候補がすでにあれば、移さずに残す方を選ぶ）
- 初期の値（初回セットアップで作る。あとで自由に変更）
  - 購入先: ヨドバシ、ビックカメラ、Amazon、楽天、無印良品、IKEA、ニトリ、ドラッグストア、スーパー
  - ジャンル: 家電、洗濯機、冷蔵庫、日用品、食品、家具、服、その他

### F5. 購入先ごとの候補（価格比較）

- 1件のメモに、購入先を複数つけられる（同じ購入先は1回だけ。最大20件）
- 候補ごとに書けるもの（どれも任意）
  - 値段（円・整数。0〜9,999,999）
  - リンク（その購入先の商品ページ。1件）
  - ひとこと（例: 「ポイント10%」「配送無料」「店頭在庫あり」。〜200文字）
  - 値段を確かめた日（値段を変えると今日の日付に自動で変わる。手で直せる）
- 詳細ページでは、値段の安い順に並べ（値段のない候補は後ろ）、いちばん安い候補に「いちばん安い」を付ける。いちばん安い候補との差額も出す（例: 「+10,800円」）
- 値段を確かめた日から30日以上たった候補には「値段が古いかも」と出す
- 候補を押すと、値段・リンク・ひとことを編集するシートを開く。リンクだけ押したときは別タブで開く

### F6. 買ったチェック

- 一覧の各行と詳細ページの名前の左にチェックボックスを出す。押すとすぐ「買った」になる（保存ボタンは不要）
- 「買った」にしたメモは、数秒「元に戻す」を出してから「欲しい」の一覧から外れ、「買ったもの」に移る
- 「買ったもの」は買った日の新しい順。チェックを外すと「欲しい」に戻る
- 買った人と買った日時を残す（どの購入先で買ったかは残さない。必要ならフェーズ2）
- おるが「買えたね！」とお祝いすることがある（F8）

### F7. リンク

- 購入先に関係しないリンク（レビュー記事・比較サイトなど）を1件のメモに最大10件。URL（必須）と表示名（任意。空なら URL のドメインを表示）
- 候補のリンク（F5）と共通の決まり
  - 貼り付けた文字列から URL を取り出す（共有で付く前後の文章を除く）
  - `http://` `https://` 以外は受け付けない（`javascript:` などを防ぐ）。2,048文字まで
  - 押すと別タブで開く（`rel="noopener noreferrer"`）
- 並べ替え・削除ができる

### F8. おる（定期的に出てくる）

Kakeibo の「おる」（`components/Oru.tsx`・`OruCameo.tsx`・`lib/oru.ts`・`public/mascot/oru-sheet.webp`）をそのまま使い、しゃべる内容だけメモ向けにする。

- 出てくるとき: アプリを開いたとき・ほかのアプリから戻ってきたときに2回に1回くらい。前に出てから5分はあける（Kakeibo と同じ `ORU_CHANCE = 0.5`・`ORU_GAP_MS = 5分`）
- 画面の右下（スマホは入力欄の少し上）から歩いてきて、ひとことしゃべって帰る。押すとすぐ帰る。吹き出しはしゃべり終わって3秒で消える
- 入力中・シートを開いている間は出さない（すぐ登録の邪魔をしない）
- メモを追加したとき・買ったを付けたときに、ときどき（5回に1回くらい・5分あける決まりは同じ）ジャンプして「メモしたよ！」「買えたね！」などと言う
- しゃべる内容
  - 普通のひとこと（例: 「欲しいもの、思いついた？」「メモしておけば忘れないよ」「お店ごとの値段、くらべてみてね」）
  - 時間帯のひとこと（Kakeibo の `timeLines` を流用し、文面をメモ向けに変える）
  - メモの数字のひとこと（例: 「ヨドバシで買うものが3件あるよ。今度まとめて行こう」「1か月前のメモ、まだ欲しい？」「洗濯機はAmazonがいちばん安いよ」「値段が古い候補があるよ」）
- 設定の「表示」で端末ごとにオフにできる。「視差効果を減らす」の端末では動かさない

## 5. 画面一覧

| 画面 | URL | 内容 |
|------|-----|------|
| 一覧（ホーム） | `/` | すぐ登録の入力欄・欲しい/買ったもの・並べ方・絞り込み・メモの一覧。PC は右に詳細 |

## 6. データ要件

### 6.1 テーブル（D1）

認証まわり（`users` / `credentials` / `sessions` / `auth_challenges` / `recovery_codes` / `invites`）は Kakeibo の migrations の該当部分をまとめて1本にして持ってくる。
メモ帳は全員で1つを共有するため、家計簿（`books`）のような区切りの表は作らない。将来1人1冊が必要になったら `space_id` を足す。

```sql
-- 購入先（どこで買うか）
CREATE TABLE stores (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  icon TEXT NOT NULL,
  color TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- ジャンル（どういうものか）。購入先とは独立
CREATE TABLE genres (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  icon TEXT NOT NULL,
  color TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE memos (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,                 -- 名前（1〜100文字）
  body TEXT NOT NULL DEFAULT '',       -- 詳細メモ（〜5,000文字）
  genre_id TEXT REFERENCES genres(id) ON DELETE SET NULL,
  done_at TEXT,                        -- 買った日時。NULL なら「欲しい」
  done_by TEXT REFERENCES users(id) ON DELETE SET NULL,
  client_id TEXT UNIQUE,               -- 電波がないときの再送で二重登録しないための端末側 ID
  created_by TEXT REFERENCES users(id) ON DELETE SET NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_memos_open ON memos(done_at, created_at DESC);
CREATE INDEX idx_memos_genre ON memos(genre_id);

-- 候補（メモ × 購入先）。1件のメモに購入先を複数、同じ購入先は1回だけ
CREATE TABLE memo_offers (
  id TEXT PRIMARY KEY,
  memo_id TEXT NOT NULL REFERENCES memos(id) ON DELETE CASCADE,
  store_id TEXT NOT NULL REFERENCES stores(id) ON DELETE CASCADE,
  price INTEGER CHECK (price IS NULL OR price BETWEEN 0 AND 9999999),  -- 円
  url TEXT NOT NULL DEFAULT '',        -- http/https のみ
  note TEXT NOT NULL DEFAULT '',       -- ひとこと（〜200文字）
  checked_on TEXT,                     -- 値段を確かめた日（YYYY-MM-DD、日本時間）
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (memo_id, store_id)
);
CREATE INDEX idx_memo_offers_store ON memo_offers(store_id);

-- 購入先に関係しないリンク
CREATE TABLE memo_links (
  id TEXT PRIMARY KEY,
  memo_id TEXT NOT NULL REFERENCES memos(id) ON DELETE CASCADE,
  url TEXT NOT NULL,                   -- http/https のみ、〜2,048文字
  label TEXT NOT NULL DEFAULT '',      -- 〜100文字
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL
);
CREATE INDEX idx_memo_links_memo ON memo_links(memo_id);
```

- 購入先を消すと、その購入先の候補も消える（`ON DELETE CASCADE`）。画面では消す前に件数を出して確認し、ほかの購入先へ移す選択肢も出す（F4）
- ID はサーバーで発行する乱数（Kakeibo と同じ）。日時は ISO 8601（UTC）で保存し、画面で日本時間に直す
- 件数の見込み: 2人で年に数百件。一覧は1回の問い合わせで候補もまとめて取り、画面側で並べ替え・2段の組み立てをする

### 6.2 API（Hono、`/api/*`）

| メソッド・パス | 内容 |
|------|------|
| `GET /api/memos?state=open\|done&store=&genre=&q=` | 一覧（候補の購入先・値段つき） |
| `POST /api/memos` | 登録（名前だけでも可。ジャンル・購入先・候補・リンクを一緒に送ってもよい） |
| `GET /api/memos/:id` | 詳細（候補・リンクつき） |
| `PATCH /api/memos/:id` | 編集（名前・詳細メモ・ジャンル。候補とリンクは全件送って置き換え） |
| `PUT /api/memos/:id/done`・`DELETE /api/memos/:id/done` | 買ったを付ける・外す |
| `DELETE /api/memos/:id` | 削除 |
| `GET/POST/PATCH/DELETE /api/stores`・`/api/genres` | 購入先・ジャンルの管理・並べ替え（削除は移し先を指定できる） |
| `GET /api/export` | 全メモを CSV（候補1つで1行）で書き出し |
| `/api/auth/*`・`/api/admin/*` | Kakeibo と同じ（ログイン・パスキー・招待・メンバー） |

- 入力チェックは zod のスキーマを `src/shared/schemas.ts` に置き、画面と API で同じものを使う（Kakeibo と同じ）
- 共有のメモ帳なので、2人が同じメモを同時に直したときは後から保存した方が残る（`updated_at` が変わっていれば「ほかの人が更新しました」と出して読み直す）

## 7. 非機能要件

| 項目 | 内容 |
|------|------|
| 速さ | 開いてから入力欄が使えるまで、2回目以降は 1 秒以内（Service Worker で画面をキャッシュ）。登録・買ったチェックは画面に先に反映し、裏で送る |
| 対応ブラウザ | iPhone の Safari（ホーム画面アプリ）、PC の Chrome / Safari / Edge の最新版 |
| アクセシビリティ | 文字と背景のコントラスト 4.5:1 以上（Kakeibo のトークンを使えば満たす）、キーボードだけで操作できる。チェックボックスは 44px 四方以上の押せる範囲 |
| 費用 | Cloudflare の無料枠の中（Workers 10万リクエスト/日、D1 5GB）。AI は使わないので費用は 0 円の想定 |
| データ保護 | D1 の Time Travel（無料プランは7日前まで戻せる）＋設定からの書き出し。Kakeibo のような週次バックアップ（R2）はフェーズ2で検討 |

## 8. 技術構成

Kakeibo と同じ構成にする。違いは「R2・AI・Web Push・Cron の大半を使わない」ことだけ。

| 層 | 技術 |
|----|------|
| 画面 | React 19 + TypeScript + Vite（PWA）、Tailwind CSS v4、lucide-react、LINE Seed JP（同梱フォント）、clsx |
| API | Cloudflare Workers + Hono（画面ファイルの配信も同じ Worker。`assets.run_worker_first: ["/api/*"]`） |
| DB | Cloudflare D1（SQLite） |
| 認証 | Kakeibo と同じパスキー（@simplewebauthn）＋リカバリーコード、招待制。実装を移植する（§8.4） |
| 入力チェック | zod（画面と API で共有） |
| Cron | 毎日1回、期限切れのセッション・認証チャレンジ・招待を消す |
| テスト | vitest（単体）＋ @cloudflare/vitest-pool-workers（D1 込みの結合テスト）＋ Playwright（E2E・画面幅ごとの見た目） |
| CI / 公開 | GitHub Actions。Kakeibo の `ci.yml`・`deploy.yml` を流用（main の CI が通ったら `wrangler deploy`） |

### 8.1 デザインの統一のしかた

Kakeibo から次をコピーして持ってくる。見た目の決まりは Kakeibo の `styles.css` の先頭コメントのとおり（白地・細い線で区切る・影とグラデーションは浮くものだけ）。**アクセントの色は Kakeibo と同じオレンジ**（`--c-brand: #cc4a0b`、ダークは `#fb923c`）をそのまま使う。

| 持ってくるもの | Kakeibo の場所 |
|------|------|
| 色・文字サイズ・アニメーションのトークン（ライト/ダーク） | `src/client/styles.css` |
| 画面の明るさの切り替え | `public/theme.js`・`src/client/lib/theme.ts` |
| シート（下から出る・払って閉じる）・トースト | `components/Sheet.tsx`・`components/Toast.tsx` |
| 金額の表示・入力 | `shared/format.ts`・`components/AmountInput.tsx` |
| カテゴリのアイコン・選択・編集（購入先とジャンルの両方に使う） | `shared/icons.ts`・`components/CategoryIcon.tsx`・`CategoryPicker.tsx`・`CategoryEditor.tsx`・`views/CategoryManager.tsx` |
| おる | `components/Oru.tsx`・`OruCameo.tsx`・`lib/oru.ts`・`public/mascot/oru-sheet.webp` |
| ログイン・パスキー・招待 | `views/AuthScreens.tsx`・`worker/routes/auth.ts`・`worker/lib/session.ts`・`worker/lib/crypto.ts`・`worker/lib/http.ts` |
| 端末内の保存・更新の検知・振動 | `lib/storage.ts`・`lib/update.ts`・`lib/haptics.ts`・`public/sw.js`・`public/_headers` |

- 共通パッケージ（モノレポや npm パッケージ）にはしない。アプリが2つ・作るのが1人なので、まとめる手間の方が大きい。コピーしたファイルの先頭に「Kakeibo の〇〇から」と書き、Kakeibo 側で直したら合わせる
- アプリが3つ目になる、またはコピー元との差が目立ってきたら、共通部分を別パッケージにまとめることを検討する
- ホーム画面で見分けられるよう、アイコンは別の絵にする（色は同じオレンジ）

### 8.2 ディレクトリ構成

```
src/client     画面（React）。views/ 画面、components/ 共通部品、lib/ 保存・テーマ・おる・一覧の組み立て
src/worker     API（Hono）。routes/（auth / memos / stores / genres / admin）、lib/（セッション・暗号・HTTP）
src/shared     画面と API で共有する型・入力チェック・日付・金額
migrations     D1 のテーブル定義（0001 認証、0002 メモ・購入先・ジャンル・候補・リンク）
public         manifest / Service Worker / アイコン / おるの画像 / _headers
test/worker    Workers 結合テスト
e2e            ブラウザでの動作確認
```

### 8.3 Kakeibo に組み込む案を採らない理由
Kakeibo の中に「メモ」タブを足せば認証やデザインを共有できるが、次の理由で別アプリにする。
- 「開いてすぐ書ける」ことが目的なので、メモだけの画面で起動したい（Kakeibo はカレンダーで起動する）
- Kakeibo は機能が多く、変更のたびに確かめる範囲が広い。メモの変更で家計簿を壊す心配をなくしたい

### 8.4 ログイン（パスキー）
- Kakeibo と同じしくみ（パスキーだけ・招待制・リカバリーコード）を移植する。使い方（Face ID で入る）は Kakeibo と同じ
- ただし**パスキーそのものは Kakeibo と別に1回登録する**。パスキーはアプリの URL（ホスト名）に結びつき、Kakeibo は自分のホスト名で登録しているため（`worker/routes/auth.ts` の `rpID`）、別の URL のメモアプリでは同じパスキーを使えない
- 同じパスキーで両方に入るには、両方を同じドメインの下に置き（例: `kakeibo.example.com` と `memo.example.com`）、パスキーの登録先を親ドメイン（`example.com`）にする必要がある。Kakeibo の今のパスキーは作り直しになるため、採らない

## 11. リスク・懸念

| リスク | 内容 | 対応 |
|------|------|------|
| iPhone でキーボードが自動で出ない | iOS の Safari・ホーム画面アプリは、利用者が押す前に入力欄へカーソルを置いてもキーボードを出さない。「開いたらすぐ打てる」はタップ1回が必要 | 入力欄を画面下の大きな的にする。どうしても0タップにしたい場合はフェーズ3の iPhone のショートカット連携で補う |
| 値段が古くなる | 値段は自分で書くので、時間がたつと実際と違う | 確かめた日を残し、30日たったら「値段が古いかも」と出す。自動取得はしない（サイトの利用規約・取得の失敗が多いため） |
| 2段表示で同じメモが何度も出る | 購入先が複数あるメモは「購入先ごと」の並べ方で各見出しに出る | 意図どおり（お店ごとに見たいため）。件数の表示は見出しごとに数える。買ったチェックはどこで押しても同じメモに効く |
| 2人の同時編集 | 同じメモを同時に直すと、後から保存した方が残る | `updated_at` で検知して知らせる（§6.2） |
| デザインのずれ | コピーした部品が Kakeibo と少しずつずれていく | コピー元を各ファイルの先頭に書く。差が大きくなったら共通化（§8.1） |
| リンクの安全 | 利用者が貼った URL を画面に出す | `http`/`https` だけ受け付け、`noopener noreferrer` で開く。CSP は Kakeibo の `_headers` を流用 |
| ログインが2つになる | Kakeibo とメモでパスキーを別々に登録する | 初回の登録だけの手間（§8.4） |
| おるの出すぎ | メモは短時間に何度も開くため、出てくる回数が Kakeibo より多くなりうる | 5分あける決まりを守る。多すぎれば確率を下げる |
