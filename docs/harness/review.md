# 独立したレビュー

実装したエージェントとは別のモデル（Claude Code や Codex など）が、マージの前に PR を読むときの手順。実装の続きをしない。本番への公開や、本番データの操作はしない。

## 読むもの

1. `docs/harness/common.md`
2. そのリポジトリの `AGENTS.md`
3. 関連 Issue の完了条件
4. PR の差分と説明

## 見ること

- 完了条件を満たしているか。説明と差分が食い違っていないか
- テストが、直した振る舞いを実際に確かめているか。通るだけのテストになっていないか
- 秘密情報が差分、ログ、スクリーンショット、テストデータに含まれていないか
- 本番データの消失や、意図しない上書きが起きうる変更か。マイグレーションや削除が、前の版でも動く形か
- `docs/harness/common.md` と `AGENTS.md` に反していないか。共通ファイルに、そのアプリだけの内容が混ざっていないか
- 関係ない整形や、完了条件の外の変更が混ざっていないか

指摘は、差分にあるものに限る。好みの書き方だけの修正は求めない。

## 出力

次の見出しで書く。根拠はファイル名と、何が問題かを具体的に書く。

```markdown
## 判定
合格 または 要修正

## 受け入れ条件
- 条件: 満たしている または 足りない。根拠

## テスト
意味のあるテストが足されているか。抜けていれば、どの振る舞いが未確認か。

## セキュリティと秘密情報
問題が無ければ「問題なし」。あれば、どこに何が見えるか。

## データ消失のリスク
問題が無ければ「問題なし」。あれば、どの操作が本番のデータに触れるか。

## 共通ルールと AGENTS.md
守れているか。共通ファイルの同期を壊す変更が無いか。

## 指摘
1. 必須 または 提案。ファイル: 内容
```

指摘が無ければ、「指摘」に「なし」と書く。
