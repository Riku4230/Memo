# 独立レビュー

実装したモデルとは別のモデル（Claude Code や Codex など）が、マージの前にプルリクエストを読むときの手順。

アプリの名前や構成はこのファイルに書かない。アプリのことは `AGENTS.md` と Issue から読む。共通の禁止事項は `docs/harness/common.md` に従う。

## 読むもの

1. `docs/harness/common.md`
2. そのリポジトリの `AGENTS.md`
3. 関連 Issue の完了条件とテスト方法
4. プルリクエストの diff と、本文に書かれた検証結果

## 見ること

- 正しさ。完了条件を満たしているか。完了条件にない挙動の変化が無いか
- テスト。完了条件を裏づける確認があるか。断言が無い、常に成功する、実装の私的な細部にしか結びつかないテストになっていないか
- シークレット。トークン、パスワード、鍵、ローカル設定の実値が diff、ログ、スクリーンショット、本文に無いか
- データ損失。本番データの削除、上書き、巻き戻し、本番へのマイグレーションが無いか。ある場合は、Issue にその操作が書いてあり、オーナーが頼んだ範囲か
- ルール。`AGENTS.md` と `docs/harness/common.md` の「頼まれずに触らないもの」に反していないか。画面を変えているのに、検証コマンドとスクリーンショットが無いか
- ハーネス。共有ファイルを変えている場合、ハーネス改善として説明されているか。`docs/harness/common.md` を変えたときに `harness-version` が上がっているか。アプリ固有の話が共有ファイルに混ざっていないか

## 出力

日本語で、次の見出しの順に書く。

### 判定

承認できる、または修正が必要。修正が必要なときは、マージの前に直すものを先に書く。

### 完了条件

満たしているものと、足りないもの。

### テスト

足るかどうか。足りなければ、どの確認を足すか。

### シークレットとデータ

問題がなければ「問題なし」。あればファイルと理由。

### ルール

`AGENTS.md` と共通ルールに対する指摘。なければ「問題なし」。

### 指摘

重大度（必須または提案）、場所、内容、期待する直し方。指摘がなければ「なし」。
